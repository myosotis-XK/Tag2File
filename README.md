# Tag2File 使用指南

Tag2File 是一个强大的标签式文件管理工具，帮助你通过标签快速组织、搜索和访问文件。它同时提供**桌面客户端**和**Web界面**，满足不同场景的使用需求。

---

## 🚀 快速上手

### 启动应用程序

直接运行 `Tag2File.exe` 即可启动程序。

您可以在同一局域网内的其他设备上通过浏览器访问具备基本查询功能网页：
* 点击开始菜单中的“web端入口”，可以看到网址和二维码，输入网址或扫描二维码即可在手机上打开Web界面。

## ✨ 核心功能详解

### 1. 标签表达式搜索

Tag2File 最强大的功能是支持复杂的标签表达式搜索，让你能够精确找到所需文件。
标签表达式与数学的集合运算一致，支持以下操作符：

| 操作符 | 含义 | 示例 | 描述 |
| :---: | :---: | :--- | :--- |
| `∩` | 交集 | `风景 & 日出` | 查找**同时包含**"风景"和"日出"标签的文件。 |
| `∪` | 并集 | `风景 ∪ 城市` | 查找**包含任一**标签的文件。 |
| `'` | 补集 | `低质量'` | 查找**不包含**"低质量"标签的文件。 |
| `(` 和 `)` | 运算顺序 | `(风景 ∪ 城市) & 高质量` | 查找包含"风景"或"城市"，且同时包含"高质量"标签的文件。 |

### 2. 标签管理 (桌面客户端)

* **管理标签**：点击 "**管理标签**" 按钮，进入标签编辑界面。
* **标签库**：从菜单栏的 "**开始**" → "**标签库**" 进入完整的标签库管理界面。

### 3. 类别管理 (桌面客户端)

* **管理类别**：点击 "**管理类别**" 按钮，进入类别编辑界面。
* **标签类别**：你可以为标签定义类别，以实现更清晰的标签组织。
* **特殊类别**：你可以将类别设置为**特殊类别**，以实现常驻的过滤功能，可以省去取补集的操作。

### 4. 文件相关功能

* **显示** 支持**缩略图**浏览模式，可以在**小**、**中**、**大**三种缩略图尺寸切换之间切换
* **排序** 支持按**文件名**、**文件大小**、**修改时间**、**随机**排序。主窗口的标签搜索结果支持**手工排序**：在空白处右键选择“排序 → 手工排序”，拖动文件或多组选中项调整位置。每个标签库共用一份排列，重启后仍保留；新文件以入库时的修改时间作为初始排序值，插入对应位置。
* **文件操作** 支持**打开**、**复制**、**剪切**、**重命名**、**删除**文件
>     注意：标签是通过文件路径来指向文件的，只有通过应用内的文件操作才能保证标签的正确更新。

## 手工排序 HTTP 接口

桌面程序启动后，Web 服务提供以下三个接口。先通过 `POST /login` 提交表单字段 `username`、`password`，后续请求沿用登录会话的 Cookie。接口使用 JSON 请求体，并显式指定标签库 `db_path`，不会切换桌面或 Web 当前选中的标签库。

| 接口（均为 POST） | 用途 | 请求字段 |
| --- | --- | --- |
| `/api/manual_order/query` | 查询给定文件的手工顺序 | `db_path`、`file_paths` |
| `/api/manual_order/move` | 将一组文件移到目标前面或后面 | `db_path`、`file_paths`、`target`、`placement` |
| `/api/manual_order/set` | 将 N 个文件按数组顺序放回它们原来占用的位置 | `db_path`、`file_paths` |

文件列表必须是非空数组，路径必须属于指定标签库，不能重复；路径支持 `/` 和 `\`，返回路径使用 `/`。排序在整个标签库中生效，真实文件内容和修改时间保持不变。

### 查询顺序

发送到 `/api/manual_order/query`：

```json
{
  "db_path": "D:/data/photos.db",
  "file_paths": ["D:/photos/C.jpg", "D:/photos/A.jpg", "D:/photos/B.jpg"]
}
```

返回给定文件按手工排序排列后的列表：

```json
{
  "success": true,
  "file_paths": ["D:/photos/A.jpg", "D:/photos/B.jpg", "D:/photos/C.jpg"]
}
```

### 移动一组文件

发送到 `/api/manual_order/move`：

```json
{
  "db_path": "D:/data/photos.db",
  "file_paths": ["D:/photos/C.jpg", "D:/photos/D.jpg"],
  "target": "D:/photos/B.jpg",
  "placement": "before"
}
```

`placement` 为 `before` 或 `after`，组内顺序采用 `file_paths` 的顺序。目标位置根据完整标签库中的相邻文件计算，包括当前筛选隐藏的文件。目标属于移动组，或该组已经位于目标指定的一侧且顺序一致时，返回无操作结果。

### 设置 N 个文件的顺序

发送到 `/api/manual_order/set`：

```json
{
  "db_path": "D:/data/photos.db",
  "file_paths": ["D:/photos/C.jpg", "D:/photos/A.jpg", "D:/photos/B.jpg"]
}
```

例如全库原顺序为 `A → X → B → Y → C`，提交 `[C, A, B]` 后为 `C → X → A → Y → B`。未提交文件保持原来的全库位置。传入全库文件时，数组就是全库的最终顺序。

通常复用所选文件的原排序值；排序值相同且需要调整次序时，只调整涉及的等值段。其他文件的位置保持不变，新文件仍以入库时的修改时间参与排序。

### 保存结果和错误

移动和设置接口使用同样的响应：

```json
{"success": true, "changed": true, "affected_count": 3}
```

`affected_count` 是实际修改排序值的文件数量，等值段调整可能涉及未提交的文件。无操作时 `changed` 为 `false`，数量为 `0`。有效写入使用单次事务，提交后发布一次通知；桌面主窗口处于手工模式时原地重排，保留选区、当前文件和滚动位置。

错误也返回 JSON，例如：

```json
{"success": false, "error": "file_not_found", "message": "文件已不在当前标签库中"}
```

| HTTP 状态 | `error` | 含义 |
| --- | --- | --- |
| 400 | `invalid_request` | 请求格式、参数或重复路径有误 |
| 401 | `unauthorized` | 尚未登录 |
| 404 | `tagbase_not_found` / `file_not_found` | 标签库或文件记录不存在 |
| 500 | `database_error` | 数据库操作失败；写事务会回滚 |

## ⚙️ 配置说明

### 桌面端 MP4 视频播放

双击 MP4 文件会打开内置视频播放器，播放列表按当前文件列表的顺序收集 MP4，并从双击的视频开始播放。优先以常见的 H.264 视频 + AAC 音频为目标，实际编码支持取决于本机 Qt 多媒体后端；无法播放时会显示提示，可点击“使用系统播放器打开”。

* 使用深色播放界面，底部统一显示进度、播放控制、时间、音量和功能菜单。支持点击或拖动进度、点击音量图标静音；双击画面或按 `F11` 切换全屏，`Esc` 退出全屏，空格播放/暂停，`←` 后退 5 秒、`→` 前进 5 秒（音量滑块聚焦时仍调整音量）。暂停时步进保持暂停，位置限制在视频起止范围内。
* 播放列表默认收起，点击底部列表图标或按 `Ctrl+L` 展开/收起。长文件名省略显示，悬停可查看完整路径。
* 底部播放模式按钮与音频播放器一样，依次切换“顺序播放 → 随机播放 → 单个循环”，默认顺序播放。顺序播放会在最后一部结束后回到第一部；随机播放在有多部视频时避开当前视频；单个循环会重播当前视频。模式仅在本次窗口中保留。
* 双击播放列表中的视频切换播放，也可以使用“上一部”“下一部”（快捷键 `Ctrl+Left`、`Ctrl+Right`）。随机模式下手动切换也会随机选择其他视频；顺序播放和单个循环模式下，手动切换按列表顺序前进或后退，首尾可切换。
* 列表标题旁的加号、“更多 → 添加视频”或 `Ctrl+O` 可追加 MP4；列表右键菜单的“从列表移除”只修改本次播放队列，不删除文件或标签。移除当前视频会播放相邻视频，清空队列则停止播放。播放列表在窗口关闭后不保留。
* 全屏播放时控制栏在鼠标静止约 2.5 秒后隐藏，移动鼠标即可唤出；暂停、拖动进度和操作菜单时保留控制栏。字幕自动避让控制栏，退出全屏后恢复之前的列表展开状态。
* “更多”菜单提供“使用系统播放器打开”。

#### SRT 字幕

打开视频时会自动读取同目录、同名的 `.srt` 文件，例如 `示例.mp4` 对应 `示例.srt`。底部“字幕”图标菜单中可选择其他 SRT，通过“显示字幕”随时关闭或恢复字幕；图标蓝色表示字幕已启用。手动选择的字幕关联仅在本次播放器窗口中保留。

字幕在视频画面底部显示，支持多行、双语、时间重叠和全屏；按照每句起止时间显示，暂停和拖动进度时同步更新。推荐 UTF-8 编码，同时兼容带 BOM 的 UTF-16 和常见 GBK/GB18030 中文字幕。字体、颜色采用播放器统一样式，SRT 中的基本样式标签会转换为普通文字。缺失或损坏的字幕不会阻止视频播放。

Windows 视频播放默认优先使用 Qt 自带的 Windows Media Foundation 后端，以避免第三方 DirectShow 字幕滤镜重复显示同名字幕；音频播放器继续使用原来的后端。若自行设置了 `QT_MULTIMEDIA_PREFERRED_PLUGINS`，该设置仍优先生效。

### Web 端 MP4 视频播放

在 Web 文件列表中点击音频或 MP4，会在新标签页打开对应播放器，原文件列表页面保留。每个播放器按当前已加载文件列表的顺序建立独立播放队列，互不覆盖；刷新播放器页面可保留队列。返回按钮在播放器标签页中打开文件列表并恢复打开播放器时的浏览位置，也可以直接切回原文件列表标签页。视频由浏览器直接解码，不进行服务器实时转码；能否播放取决于浏览器对文件内部编码的支持。

* 深色播放界面，播放列表默认收起。支持播放/暂停、拖动进度、静音、桌面浏览器音量调整和全屏；窄屏使用侧边抽屉列表。
* 底部最左侧按钮切换“顺序播放 → 随机播放 → 单个循环”，规则与桌面端一致。顺序播放首尾循环，随机模式避开当前视频，单个循环仍允许手动上一部/下一部。
* 列表条目右侧的移除按钮只影响播放队列。“添加视频”可重新加入当前文件列表中已移除的视频；选择其他文件范围请返回文件列表。队列在当前浏览器标签页内保留，播放模式和手动字幕关联在刷新后重置。
* 自动读取服务器上与视频同目录同名的 `.srt`；字幕菜单支持开关和选择本机 SRT。手动字幕由服务器临时转换为 WebVTT，不保存或覆盖任何字幕文件，单个字幕文件上限为 8 MB。编码与桌面端相同。
* 全屏播放时控制栏约 2.5 秒无操作后隐藏，移动鼠标或点击画面唤出；双语字幕自动避让控制栏。支持空格播放/暂停、`←` 后退 5 秒、`→` 前进 5 秒、`F` 或双击画面全屏、`Ctrl+Left` / `Ctrl+Right` 切换视频，桌面浏览器也可用 `Ctrl+L` 切换列表（若被浏览器地址栏快捷键占用，请点击列表按钮）。暂停时步进保持暂停，位置限制在视频起止范围内；音量滑块和其他输入控件聚焦时保留控件自己的方向键行为。
* 登录后使用当前标签库的文件访问规则读取视频和配套字幕。文件流支持 HTTP Range / HEAD，可按需读取大文件；不支持的编码、无权访问、文件丢失或登录过期会显示提示。浏览器阻止自动播放时，点击播放按钮即可。

### 配置文件

默认情况下，配置文件存储在以下位置：
* `Tag2File/config/config.ini`  

你可以在配置文件中修改应用的各种参数

### 标签库存储位置

默认情况下，标签库数据存储在以下位置：
* `Tag2File/data/tagbase/`

### 缩略图缓存位置

默认情况下，缩略图缓存存储在以下位置：
* `Tag2File/data/cache/image`

## 💡 高级技巧

1.  **高效使用标签表达式**
    * 善用括号组合复杂条件。
    * 记住常用的标签组合，提高搜索效率。
    * 结合特殊类别过滤，可以更快速地定位文件。
2.  **性能优化**
    * 尽量不要使查询结果包含过多文件，避免应用卡顿。
    * 使用固态硬盘可以大幅提升缩略图加载速度。

## 关于打包
在根目录下执行以下命令打包：
```bash
pyinstaller --name Tag2File --windowed --onefile --icon=data/icon/app/favicon.ico main.py
```
打包完成后将dist文件夹下的Tag2File.exe应用程序移动根目录下，然后运行即可。
